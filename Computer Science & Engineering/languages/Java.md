자바는 1995년 선 마이크로시스템즈(현 오라클)에서 발표한 객체지향프로그래밍 언어로 기업형 백엔드 시스템, 안드로이드 어플리케이션 개발 등에서 주로 사용되어 왔다.

---

자바의 핵심 특징

1. JVM(자바 가상 머신) 기반의 독립성
- C/C++ 코드에서 운영체제의 고유 기능이 담긴 헤더나 시스템 호출을 쓰면 특정 운영체제에서만 컴파일되거나 동작하는 문제가 있다.
- 자바는 운영체제와 무관하게 설계된 자바 표준 API만 사용하여 코드(.java 파일)를 작성하고, 이를 자바 컴파일러(javac)로 먼저 바이트코드(.class 파일)로 컴파일한 뒤, 실행 시점에 각 운영체제용 JVM이 바이트코드를 각자의 운영체제에 맞추어 기계어로 변환 후 실행한다.
2. 순수 객체 지향 언어
3. Garbage Collection(자동 메모리 관리)
4. 강력한 멀티스레드 지원
5. 엄격한 컴파일러(javac)와 강력한 정적 타입 시스템

---

자바의 문법

1. 클래스와 객체지향프로그래밍
- 클래스: 객체를 만들기 위한 설계도로 필드(변수)와 메서드(함수)로 구성된다.
- 생성자: 객체가 생성될 때 초기화를 담당하는 특별한 메서드로 반환 타입이 없으며 클래스 이름과 동일하다. 
- 상속: extends 키워드를 사용하여 부모 클래스의 기능을 자식 클래스가 물려받아 재사용 및 확장한다.

2. 인터페이스와 추상화
- 추상 클래스: abstract 키워드를 사용한다.
- 인터페이스: interface 키워드를 사용하며, 클래스가 구현해야 하는 표준 규격을 정의한다.

3. 접근 제어자
- private: 해당 클래스만 접근 가능
- default: 같은 패키지만 접근 가능
- protected: 패키지가 다르더라도 자식 클래스는 접근 가능
- public: 외부 패키지 등 전체 영역에서 접근 가능

4. 컬렉션 프레임워크: 다수의 데이터를 효율적으로 저장하고 관리하기 위한 표준 자료구조 인터페이스이다.
- List: 순서가 있고 중복을 허용한다. (ex. ArrayList, LinkedList)
- Set: 순서가 없고 중복을 허용하지 않는다. (ex. HashSet, TreeSet)
- Map: 키와 값의 쌍으로 저장되며, 키는 중복될 수 없다. (ex. HashMap)

5. static
- static 변수
- static 메서드
- static 블록
- static 중첩 클래스

6. **Annotation(어노테이션): 다른 언어의 주석은 사람만 읽는 설명이라면, 자바의 어노테이션은 컴파일러나 프레임워크가 읽고 특정 동작을 수행하도록 지시하는 주석이다.** 어노테이션의 종류에 따라 컴파일 단계에서 검사 후 소멸되는 경우도 있고 실행 시점까지 남아 메모리에 로딩되는 경우도 있다.
- **컴파일러 체크용(실수 방지): @Override**
- 코드 자동 생성용(ex. Lombok 라이브러리): @Getter, @Setter 등을 붙이면 컴파일 후 바이트코드(.class 파일)에 메소드가 자동으로 생긴다.
- **프레임워크에 지시용(Spring Framework): 객체 생성(@RestController), URL 매핑(@GetMapping), 예외 처리 등을 프레임워크가 대신 하도록 메타데이터를 전달한다.**
